> 但**没碰过单片机、没写过嵌入式代码**。看不懂的地方可以先跳过，标注了 ⭐ 的是重点。

## 1. 先把机器人跑起来（不读代码也能做）

### 1.1 你需要的东西

- 机器人本体（已经装好 18 个舵机）
- ST-LINK V2 下载器（或 USB 转串口模块）
- 5V / 10A 舵机电源（**不能**用单片机板子上的 5V 给舵机供电）
- 电脑（装了 Git + 一个能打开的编辑器；项目自带便携 VSCode 方案见 `tools/lab/README-lab.md`）

### 1.2 编译

在项目根目录双击：

```
tools\lab\build.bat
```

看到 `[完成] 产物：build\Debug\STM32Hexapod.elf / .hex / .bin` 就是成功了。
`build\Debug\STM32Hexapod.hex` 就是要烧进单片机的文件。

### 1.3 烧录

```
tools\lab\flash.bat          （默认走 ST-LINK / SWD）
tools\lab\flash.bat COM4     （走串口，需要 BOOT0 跳线）
```

### 1.4 第一次上电（⚠️ 安全）

1. **先不给舵机供电**，只插 USB：看板子上电、没异味。
2. 把机器人**架空**（四条腿悬空 / 侧放），再插舵机电源。
3. 你会看到 18 个舵机依次转到 90°（每 300 ms 一个），然后六条腿摆到站姿。
4. 有"哒哒哒"的堵转声或者腿顶到极限 → **立刻断电**。

> 为什么先转 90°？因为按这套装配，**舵机 90° = 那条腿竖直向上**（装配中位）。
> 先到中位再摆站姿，动作最小、最不容易撞坏。

## 2. 机器人身上有什么

```
      电脑 / U 盘
          │ （编译 + 烧录）
          ▼
   ┌──────────────┐   I2C 两根线（SDA 数据、SCL 时钟）
   │ STM32F103C8T6│────────────────┬────────────────┐
   │  （大脑）     │                ▼                ▼
   └──────────────┘        ┌──────────────┐  ┌──────────────┐
                           │  PCA9685 板1 │  │  PCA9685 板2 │
                           │  16 路 PWM   │  │  16 路 PWM   │
                           └──────┬───────┘  └──────┬───────┘
                                  │ 9 路            │ 9 路
                                  ▼                 ▼
                           腿 1~3 的舵机        腿 4~6 的舵机
                           （每腿：髋、股、膝）
```

### 2.1 三个角色

| 部件 | 是什么 | 在代码里的位置 |
|---|---|---|
| **STM32F103C8T6** | 单片机，"大脑"。主频 72 MHz，64 KB Flash、20 KB RAM | `Core/Src/main.c` |
| **PCA9685** | 舵机驱动芯片。单片机只有几个 PWM 引脚，不够 18 路，所以用它扩展成 16 路 | `Core/Src/pca9685.c` |
| **MG90S 舵机** | 小舵机。给它一个 PWM 信号，它就转到对应角度 | 不需要代码，只需要"角度 → 信号"的换算 |

**为什么两块 PCA9685？** 一块只有 16 路，18 个舵机不够。板 1 管腿 1~3（9 个），板 2 管腿 4~6（9 个）。

### 2.2 接线里最容易踩的坑

- **两块板 I2C 地址不一样**：板 1 是 `0x40`，板 2 因为焊错了一个引脚（A0 接到了 A5）变成了 `0x60`。
  代码里写的 `0x80` / `0xC0` 是"含读写位的 8 位地址"，等于 `0x40<<1` / `0x60<<1`。
- **共地**：单片机 GND 和舵机电源 GND 必须接在一起，否则 I2C 通信会乱。
- **舵机电源要够**：18 个 MG90S 堵转时电流很大，5V 10A 是基本要求。

## 3. 舵机到底怎么被"控制"

### 3.1 一句话版本

> 给舵机发送**周期 20 ms** 的方波，其中**高电平持续 0.5~2.5 ms**，舵机就转到 0°~180°。

```
      ┌────┐                    ┌────┐
      │    │                    │    │          ← 高电平 1.5 ms = 90°
──────┘    └────────────────────┘    └──────    ← 周期 20 ms（频率 50 Hz）
```

- 高电平 0.5 ms → 0°
- 高电平 1.5 ms → 90°（中位）
- 高电平 2.5 ms → 180°

### 3.2 代码里的换算

PCA9685 内部是 12 位计数器（0~4095），20 ms 对应 4096 个计数，所以：

```
时间 0.5 ms  → 计数 4096 × 0.5/20  ≈ 102
时间 2.5 ms  → 计数 4096 × 2.5/20  ≈ 512
```

于是 `pca9685.c` 里这一行（约第 46 行）：

```c
uint16_t off = 102 + angle * (512 - 102) / 180;
```

- `angle = 0` → `off = 102`
- `angle = 90` → `off = 307`
- `angle = 180` → `off = 512`

**你以后调角度只关心 `angle`（0~180 的整数），不用管 `off`。**

### 3.3 为什么"角度"能当指令

MG90S 内部有电位器测角度、有控制电路比较"现在角度"和"目标角度"，误差驱动电机转。
所以**它自己是闭环的**，你只要一直发目标 PWM，它就自己转到位。代码里只需要更新一次目标值。

## 4. 一条腿的几何：为什么是两节

看一条腿的侧面（把髋关节看成固定不动的点）：

```
                     中性姿态轴（舵机 90°/90° 时，整条腿朝这条线）
                          ↑
                          │
        髋关节 ●───────────┘   ← 腿从这里伸出去
               \
                \  股连杆 L2 = 57.9 mm（"大腿"）
                 \
                  ● 膝关节（第二个舵机）
                   \
                    \  胫连杆 L3 = 110 mm（"小腿"）
                     \
                      ● 脚尖（落地点）
```

- **髋关节**：绕**竖直轴**转，决定腿朝哪个方向伸出去（前、侧、后）。它不影响"腿伸多高"。
- **股关节（∠1）**：在**竖直平面内**抬/落股连杆。
- **膝关节（∠2）**：在**竖直平面内**弯折胫连杆。

### 4.1 三个关键事实

1. **髋关节是"水平面"，另外两个关节是"竖直面"。** 所以整条腿其实可以拆成两层：
   先在水平面上选方向（1 个角），再在竖直面上算两个角。这就是"3 个舵机 → 1 + 2"的由来。
2. **竖直面内只有两节**（股 + 胫），所以叫**两自由度平面臂**。两节长度固定，能到的点构成一个
   **圆环**（不是整个圆）：
   ```
   最近： hypot(57.9, 110) = 124.3 mm   ← 因为膝关节只能 ±90°，再折就断了
   最远： 57.9 + 110      = 167.9 mm   ← 完全伸直
   ```
   > 记住这个 `124.3 ~ 167.9`，后面全靠它判断"这个位置能不能到"。
3. **舵机 90° 不是"腿水平"，而是"腿朝上"**（你实测的装配方式）。所以代码里到处是
   `servo = 90 + ∠`：∠=0 时舵机 90°，腿朝上；∠ 变正/负，腿就前后摆。

### 4.2 为什么要"往上"装

因为胫连杆比股连杆长很多（110 vs 57.9）。如果 90° 时腿朝下，站立时两个关节都要转很大角度，
舵机接近极限；朝上装，站立时两个角都在 70° 左右，还有余量。代码里 `leg_ik.h` 的
`LEG_IK_NEUTRAL_UP` 就是控制这个方向的开关（1 = 朝上）。

## 5. 三角函数速成（高一能懂版）

代码里只用到 4 个东西，**不需要会推导，只需要会用**。

### 5.1 直角三角形里的 sin / cos

```
      /|
     / │ 对边
斜边/  │
   /___│
    邻边
```

- `sin θ = 对边 / 斜边`
- `cos θ = 邻边 / 斜边`
- `tan θ = 对边 / 邻边`

例：一根长 110 mm 的杆，和水平方向成 30°：
- 它升高了 `110 × sin30° = 55 mm`
- 它水平方向伸出 `110 × cos30° = 95.3 mm`

**代码里的用法**：`L3 * sinf(t2)` 就是"胫连杆在竖直方向上的投影"，`L3 * cosf(t2)` 是水平投影。

### 5.2 反三角函数：知道比值，求角度

- `acos(x)`：已知 cos 值，求角度。例：`cos = 0.5` → `acos(0.5) = 60°`。
- `atan2(y, x)`：已知一个点的坐标 (x, y)，求"从原点指向这个点的方向角"。
  - `atan2(1, 1)` = 45°
  - `atan2(1, 0)` = 90°（正上方/正左方，看你怎么定义轴）
  - `atan2(0, -1)` = 180°

`atan2` 比 `atan(y/x)` 好用的地方：它**自动判断象限**，x=0 也不会除零爆炸。
代码里 `atan2f()` 就是 `atan2` 的单精度版本。

### 5.3 余弦定理（初中/高一都学过）

任意三角形：

```
        b
   ┌─────────┐
   │ ╲       │
 c │  ╲      │ a        c² = a² + b² − 2ab·cosC
   │   ╲     │          （C 是 a 和 b 的夹角）
   │    ╲    │
   │     ╲   │
   └─────────┘
```

变形一下，就能**由三条边求夹角**：

```
cos C = (a² + b² − c²) / (2ab)
```

这就是 `leg_ik.c` 里算膝关节角度的公式。

### 5.4 度 vs 弧度

- 代码里 `sinf/cosf/acosf/atan2f` 全部用**弧度**（π ≈ 3.14159 弧度 = 180°）。
- 1 弧度 ≈ 57.3°；换算：`弧度 = 度 × π / 180`，`度 = 弧度 × 180 / π`。
- 代码里 `rad * 57.29578f` 就是把弧度换成度。

## 6. 逆运动学：从脚尖位置算两个角

**正运动学**：知道角度 → 算脚尖在哪（容易）。
**逆运动学（IK）**：知道脚尖要在哪 → 反推角度（难一点，也就是代码在干的事）。

### 6.1 第 1 步：髋关节（水平面）

给脚尖坐标 `(x, y, z)`：x 向前、y 向左、z 向上。

```
hip = atan2(y, x)
```

- 脚尖正前方（x>0, y=0）→ `hip = 0°`
- 脚尖正左方（x=0, y>0）→ `hip = 90°`
- 脚尖正右方（x=0, y<0）→ `hip = −90°`

对应 `leg_ik.c` 第 52 行 `angles.hip = atan2f(y, x);`

### 6.2 第 2 步：把问题压成二维

髋关节转过去之后，腿只在**一个竖直平面**里动。所以只需要：

```
r = √(x² + y²)      ← 脚尖离髋轴多远（水平距离）
u = z               ← 沿中性轴的分量（腿朝上装时 u = z）
d = √(r² + u²)      ← 髋关节到脚尖的直线距离
```

`d` 就是第 4 章说的那个"必须落在 124.3 ~ 167.9"的距离。
代码第 55 行 `float radial = sqrtf(x*x + y*y);`，第 60 行左右算 `d`。

**如果 d 超出范围怎么办？** 旧代码直接返回全 0（腿会突然甩到 0°，很危险）。
现在的代码把目标点**沿视线缩放到边界上**（方向不变、只改长度），见 `leg_ik.c` 第 70~90 行。

### 6.3 第 3 步：余弦定理求膝关节 ∠2

三角形：髋 → 膝（长 L2=57.9）→ 脚尖（长 L3=110），第三边是 d。

```
cos∠2 = (d² − L2² − L3²) / (2·L2·L3)
∠2 = acos(...)           ← 取"正的一支"
```

代码第 89 行 `angles.tibia = acosf(cosTibia);`

> 为什么取正的一支？因为一个 d 对应两种弯法（膝盖往里弯/往外弯），物理上只能选一种。
> 如果实际装反了，改 `gait.c` 里的 `DIR_TIBIA[腿号]` 为 `-1`，而不是改公式。

### 6.4 第 4 步：求股关节 ∠1

```
φ = atan2(r, u)                        ← 髋 → 脚尖的视线方向
β = atan2(L3·sin∠2, L2 + L3·cos∠2)     ← 视线和股连杆的夹角
∠1 = φ − β
```

代码第 99~104 行就是这个。

### 6.5 拿中左腿的 home 位置算一遍（跟着算，超有成就感）

目标：`x = 0, y = 117.2, z = −75.2`（单位 mm）

```
第1步  hip = atan2(117.2, 0) = 90°
第2步  r = √(0² + 117.2²) = 117.2
       d = √(117.2² + 75.2²) = 139.2       ✓ 在 124.3~167.9 内
第3步  cos∠2 = (139.2² − 57.9² − 110²) / (2×57.9×110)
            = (19377 − 3352 − 12100) / 12738
            = 0.309  →  ∠2 = 72.0°
第4步  φ = atan2(117.2, −75.2) = 122.7°
       β = atan2(110×sin72°, 57.9 + 110×cos72°)
         = atan2(104.6, 91.9) = 48.7°
       ∠1 = 122.7 − 48.7 = 74.0°
第5步  两个角都在 ±90° 内，不用夹
```

### 6.6 第 5 步：限幅

最后把两个角夹到 `±90°`（`leg_ik.c` 末尾）。这是机械行程，超了会顶死。

## 7. 从 IK 角度到舵机角度（角度层）

IK 算出来的是**几何角**，但舵机要的是 **0~180 的值**，而且左右腿镜像、个别舵机可能装反。
这层换算全在 `gait.c` 里：

```c
servo = 90 + 方向 × (IK角度 − 该关节的中位角) + 微调
然后夹到 [最小, 最大]
```

对应代码（`gait.c` 的 `joint_angle()`，约第 111 行）：

```c
float servo = SERVO_MID_DEG + (float)dir * (ikDeg - midDeg);
if (ch < 18) servo += (float)SERVO_TRIM[ch];
if (servo < minDeg) servo = minDeg;
if (servo > maxDeg) servo = maxDeg;
```

### 7.1 三个关节各自的参数

| 关节 | 中位角 MID | 方向 DIR | 软限位 |
|---|---|---|---|
| 髋 | 左腿 90°、右腿 −90° | 左 +1、右 −1 | 15 ~ 165 |
| 股 | 0° | **−1**（实测装法，方向相反） | 5 ~ 175 |
| 膝 | 0° | +1 | 5 ~ 175 |

举例（1 号腿 = 前左腿，`hip=50°, ∠1=74°, ∠2=72°`）：

```
髋：servo = 90 + (+1)×(50 − 90)  = 50
股：servo = 90 + (−1)×(74 − 0)   = 16      ← 注意是 90 − 74
膝：servo = 90 + (+1)×(72 − 0)   = 162
```

右腿（4 号腿，`hip=−50°`）：

```
髋：servo = 90 + (−1)×(−50 − (−90)) = 90 − 40 = 50   ← 对称，也对
```

> 股关节为什么是 −1？因为那个舵机装上去以后，"角度变大"对应的是股连杆往另一个方向倒。
> 这种"机械装反"不用改公式，改一个系数就行——这正是 `DIR` 表存在的意义。
> 如果你哪天把舵机拆下来重装成反方向，把 `DIR_FEMUR` 全改回 `+1`、同时 `FEMUR_MID_DEG` 保持 0 即可。

### 7.2 为什么要"中位角"

因为舵机 90° 不代表"几何 0°"。这套装配里：
- 舵机 90° 时股连杆与中性轴重合 → 所以股关节的中位角是 0°；
- 舵机 90° 时整条腿朝上 → 髋关节的中位角是 90°（左腿）。

**如果哪天换了装配方式，只需要改这几个宏/表，IK 公式一行都不用动**：
`HIP_MID_DEG[]`、`FEMUR_MID_DEG`、`TIBIA_MID_DEG`、`DIR_*[]`、`SERVO_TRIM[18]`。

## 8. 代码结构导读（文件地图）

```
Core/
├── Inc/
│   ├── leg_ik.h        ← 腿长、关节限位、LegAngles 结构体（改参数先看这里）
│   ├── gait.h          ← 对外函数声明：Gait_Init / Gait_TripodStep / Gait_SetFoot …
│   ├── pca9685.h       ← 驱动芯片的地址和函数声明
│   └── main.h          ← CubeMX 生成，一般不用改
└── Src/
    ├── leg_ik.c        ← 【数学层】逆运动学：脚尖坐标 → 三个角
    ├── gait.c          ← 【控制层】六条腿的站姿、步态、角度换算、写舵机
    ├── pca9685.c       ← 【驱动层】I2C 通信、PWM 寄存器
    └── main.c          ← 【入口】初始化 → 摆中位 → 摆站姿 → 主循环
```

**自下而上三层，越往下越"接近硬件"：**

```
IK 层（数学）        输入：脚尖坐标 mm        输出：三个角（弧度）
    ↓
角度层（换算）       输入：三个角            输出：0~180 的舵机值 + 限幅
    ↓
驱动层（硬件）       输入：0~180             输出：I2C → PCA9685 → PWM
```

**调试口诀**：腿的**角度不对**看 IK 层；**方向反了/偏几度**看角度层；**完全不动**看驱动层（I2C 地址、接线）。

## 9. 逐行读三个核心文件

### 9.1 `leg_ik.h`（参数头文件）

```c
#define LEG_L1  22.3f    /* 髋座水平偏移（实测，竖直面解算不用它） */
#define LEG_L2  57.9f    /* 股连杆：股关节转轴 → 膝关节转轴（实测） */
#define LEG_L3  110.0f   /* 胫连杆：膝关节转轴 → 足尖（实测） */
#define LEG_JOINT_MAX_DEG  90.0f
#define LEG_IK_NEUTRAL_UP  1     /* 1 = 舵机 90° 时整条腿朝上 */
#define LEG_REACH_MAX  (LEG_L2 + LEG_L3)                        /* 167.9 */
#define LEG_REACH_MIN  (__builtin_sqrtf(LEG_L2*LEG_L2 + LEG_L3*LEG_L3))  /* 124.3 */
```

`LegAngles` 就是三个 `float`（hip / femur / tibia），单位**弧度**。

### 9.2 `leg_ik.c`（数学层）

函数只做五件事，注释里写得和本文第 6 章一一对应：

1. 第 52 行：`hip = atan2f(y, x);`
2. 第 55~90 行：算 `r`、`d`，处理越界（沿视线缩放）
3. 第 89 行：`tibia = acosf((d²−L2²−L3²)/(2·L2·L3))`
4. 第 99~104 行：`φ`、`β`、`femur = φ − β`
5. 末尾：夹到 ±90°

**你不需要会推导**，但要能对号入座：看到 `acosf` 就知道"在算膝关节"，看到 `atan2f` 就知道"在算方向角"。

### 9.3 `gait.c`（控制层）

分四块，从上往下看：

| 区域 | 行号（约） | 内容 |
|---|---|---|
| ① 数据表 | 30~105 | `LEG_HOME` 六腿站姿坐标、`GROUP` 三角分组、通道表、方向表、微调表 |
| ② 换算 | 107~155 | `joint_angle()`、`hip_angle()`、`femur_angle()`、`tibia_angle()`、`write_leg()` |
| ③ 功能 | 157~300 | `Gait_Init` / `Gait_Home` / `Gait_SetFoot` / `Gait_SetJointAngles` / `Gait_TripodStep` / `Gait_WalkSteps` |
| ④ 注释 | 文件头 | 每张表怎么来的、对应舵机值是多少 |

**`LEG_HOME` 是最值得先看懂的表**：

```c
static const FootPos LEG_HOME[LEG_NUM] = {
    { 75.3f,  89.7f, -75.2f},  /* 1 前左 */
    {  0.0f, 117.2f, -75.2f},  /* 2 中左 */
    {-75.3f,  89.7f, -75.2f},  /* 3 后左 */
    { 75.3f, -89.7f, -75.2f},  /* 4 前右 */
    {  0.0f,-117.2f, -75.2f},  /* 5 中右 */
    {-75.3f, -89.7f, -75.2f},  /* 6 后右 */
};
```

每个数 = 那条腿脚尖相对**自己髋关节**的坐标（mm）。x 前、y 左、z 上。
六条腿的 `r`（水平距离）都是 117.2，`z` 都是 −75.2，只是方向不同。

> 想改站姿就改这张表，改完跑 `python tools\ik_check.py` 看舵机值会不会撞限位。

### 9.4 `pca9685.c`（驱动层）

只做三件事：

1. `PCA9685_Init()`：设置两块板的分频值（121 → 50 Hz）、唤醒芯片
2. `PCA9685_Set_Servo_Angle(channel, angle)`：角度 → 计数 → 写 4 个寄存器
3. 按 `channel` 判断用哪块板：`channel < 9` 用板 1（`hi2c1`），否则用板 2（`hi2c2`，`ch = channel − 9`）

### 9.5 `main.c`（入口）

关键顺序（约 92~120 行）：

```c
MX_GPIO_Init();  MX_I2C1_Init();  MX_I2C2_Init();   // 硬件初始化

PCA9685_Init(&hi2c1, &hi2c2);                       // 点亮两块驱动板
for (int ch = 0; ch < 18; ch++) {                   // 18 路先后到 90°（装配中位）
    PCA9685_Set_Servo_Angle(ch, 90);
    HAL_Delay(300);
}
HAL_Delay(500);
Gait_Init();                                        // 六条腿摆到站姿

while (0) { ... }                                   // ⚠️ 这里永远是 0，进不去
```

**`while (0)` 是个坑**：原厂代码里留了一段 0~180° 扫描的死代码，`while (0)` 让它永远不执行。
想让机器人真的走起来，要把它改成 `while (1)` 并在里面放步态（见第 11 章实验 5）。

## 10. 步态：三角步态怎么走路

六足昆虫走路不用六条腿一起动，而是分成两组轮流：一组抬起来往前迈，另一组撑着地推身体。

```
A 组：腿 1、3、5（前左、后左、中右）
B 组：腿 2、4、6（中左、前右、后右）
```

这样一个周期 `phase` 从 0 到 1：

```
phase:  0.0 ─────────── 0.5 ─────────── 1.0
A 组:   [抬腿 + 前迈........] [撑地 + 后推.......]
B 组:   [撑地 + 后推.......] [抬腿 + 前迈.......]
```

对应 `Gait_TripodStep(stride, lift, phase)`：
- 摆动相的腿：`x` 从 `−stride/2` 扫到 `+stride/2`，同时 `z += lift × sin(π×进度)`（画个弧抬起再落下）
- 支撑相的腿：`x` 从 `+stride/2` 扫回 `−stride/2`（把身体往前推）

**为什么用 `sin(π×进度)`？** 因为 `sin` 在 0~π 是一个"拱形"：开始和结尾都是 0（贴地），中间最大（抬到最高），
正好是抬腿-落地的形状，而且两端平滑、不会"啪"地砸地。

参数建议：`stride` 20~30 mm，`lift` 10~15 mm（再大会先撞膝关节 ±90° 限位）。

## 11. 五个动手实验（从易到难）

> ⚠️ 所有实验都**先架空**、手放在电源开关上。改完代码要重新 `build.bat` + `flash.bat`。

### 实验 1：只让一个舵机转

在 `main.c` 的 18 路 90° 循环之后加一行：

```c
PCA9685_Set_Servo_Angle(0, 120);   /* 0 号通道 = 1 号腿的髋关节 */
HAL_Delay(2000);
PCA9685_Set_Servo_Angle(0, 90);
```

看：1 号腿的髋是不是往一侧转？

### 实验 2：单腿摆到指定位置

```c
Gait_Home();                          /* 先站稳 */
Gait_SetFoot(2, 0.0f, 117.2f, -45.2f);   /* 2 号腿抬高 30 mm */
HAL_Delay(1000);
Gait_Home();
```

看：2 号腿抬起来了吗？改数字试试（`z` 从 −75.2 开始，改成 −45.2 是抬高，−90 是往下伸）。

### 实验 3：单腿画圆

```c
Gait_Home();
for (int k = 0; k <= 36; k++) {
    float t = (float)k / 36.0f * 6.2831853f;      /* 0 ~ 2π */
    Gait_SetFoot(2,
                 0.0f    + 25.0f * cosf(t),        /* x 左右摆 */
                 117.2f,                            /* y 不变 */
                 -75.2f  + 25.0f * sinf(t));       /* z 上下摆 */
    HAL_Delay(30);
}
Gait_Home();
```

看：脚尖画圆了吗？这是验证"角度方向对不对"最直观的实验。

### 实验 4：改站姿高度

把 `gait.c` 里 `LEG_HOME` 六个 `z` 从 `-75.2f` 改成 `-85.0f`，重新编译烧录。
看：身体是不是变高了？（`z` 越负 = 脚离身体越远 = 身体越高）

改完先跑 `python tools\ik_check.py`，看到"全部通过"再烧。

### 实验 5：让它走两步

把 `main.c` 里的 `while (0)` 改成 `while (1)`，并把里面换成：

```c
while (1) {
    for (int k = 0; k < 20; k++) {         /* 一个周期 20 帧 */
        Gait_TripodStep(25.0f, 10.0f, (float)k / 20.0f);
        HAL_Delay(10);                      /* 10ms × 20 = 200ms 一步 */
    }
}
```

架空看腿的动作对不对，再放地上（记得先站稳、地面不要太滑）。

## 12. 常见问题（FAQ）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 上电后腿往**下**转，不是朝上 | 装配方向和代码假设不一致 | `leg_ik.h` 里 `LEG_IK_NEUTRAL_UP` 改成 `0` |
| 某条腿**转反**了 | 那个舵机装的方向不同 | `gait.c` 里对应的 `DIR_HIP/DIR_FEMUR/DIR_TIBIA` 改 `-1` |
| 某个关节**固定偏几度** | 摇臂没对正 | `SERVO_TRIM[腿号*3 + 0/1/2]` 里加减 |
| 六条腿的**髋整体**都偏同一角度 | 中位没调好 | 改 `HIP_MID_DEG[]` |
| 腿伸不直 / 顶死 / 哒哒响 | 目标点超出 `124.3~167.9` | 改 `LEG_HOME` 的 z 或 r，跑 `ik_check.py` 检查 |
| 某个舵机完全不动 | 接线/通道号错，或板 2 地址错 | 检查 `CH_*` 表；板 2 是 `0x60`（写 `0xC0`） |
| 舵机抖动、乱转 | 电源不够 / 没共地 | 换 5V 10A 电源，GND 连一起 |
| 编译报 `cmake` 找不到 | 工具链不在 PATH | 用 `tools\lab\build.bat`，它会自动找 |
| `while (0)` 里的代码不执行 | 那是故意的 | 实验 5 改成 `while (1)` |

## 13. 术语表

| 术语 | 意思 |
|---|---|
| **MCU / 单片机** | 一颗小电脑芯片，跑你写的代码 |
| **I2C** | 两根线的通信协议（SDA 数据 + SCL 时钟），一个主机可以挂很多从机 |
| **PWM** | 脉冲宽度调制。用"高电平持续多久"传递信息，舵机就是用这个 |
| **寄存器** | 芯片内部的可读写小格子，写进去就改变芯片行为 |
| **IK（逆运动学）** | 已知末端位置，反推关节角度 |
| **自由度（DOF）** | 能独立运动的关节数。这条腿竖直面内是 2 个 |
| **工作空间** | 腿能到的范围。这里是距离髋 124.3~167.9 mm 的圆环 |
| **限位** | 机构或舵机能转到的最大/最小角度 |
| **闭环** | 舵机自己测角度、自己纠正，你只给目标值 |
| **步态（gait）** | 多条腿协调运动的方式，三角步态是最常见的一种 |

### 数学符号

| 符号 | 读法 | 意思 |
|---|---|---|
| ∠1 | 角一 | 股关节角度（相对中性轴） |
| ∠2 | 角二 | 膝关节角度（相对股连杆延长线） |
| φ (phi) | fai | 髋 → 脚尖的视线方向角 |
| β (beta) | beita | 视线与股连杆的夹角 |
| d | — | 髋关节到脚尖的直线距离 |
| r | — | 脚尖到髋轴的水平距离 |
| √ | 根号 | 开平方 |
